# QuizSync AI — 功能规格

术语约定：**会话（session）** = 一次识别请求，对应一次截图，是历史记录的一条；**题目（question）** = 会话内的一道题，一个会话可含 0..N 道题。

---

## 1. 角色与拓扑

| 角色 | 职责 |
|---|---|
| Windows（主机） | 截屏采集、**唯一**的 AI 调用方、与 AI API Key 的唯一持有者、内置 HTTP + WebSocket 服务端、主数据库 |
| Android（采集端） | 悬浮球截屏、把图片上传给 Windows、接收并显示结果、本地缓存历史 |
| AI 服务（外部） | 多模态模型，接收整张截图，返回结构化题目与答案 |

- 默认部署在同一局域网。Android 主动连 Windows，Windows 不主动连 Android。
- Windows 离线时：Android 仍可浏览历史；新的截屏进本地队列，等 Windows 上线后自动上传分析（见 `data-model.md` 的离线队列）。
- 不做公网穿透、不做中继服务器。

## 2. Windows 端功能

### 2.1 截屏采集

| 方式 | 说明 |
|---|---|
| 全局热键 | **只有两个**（M46 第 1 条）：**截屏识别**（默认 `F8`）与**多页模式**（默认 `F9`），都可在设置里改；截取鼠标所在显示器的全屏 |
| 托盘菜单 | 托盘图标右键 → 「截取屏幕」/「从剪贴板读取」/「显示主窗口」/「设置」/「退出」 |
| 剪贴板监听 | 开关式（默认开）。检测到剪贴板出现新图片时自动开始分析 —— 用户可用系统 `Win+Shift+S` 截完即出结果，这是最省操作的通路 |
| 拖入 / 粘贴 | 主窗口支持把图片文件拖进来，或按 `Ctrl+V` 粘贴剪贴板图片 |

- **剪贴板图片的取法**（用户反馈 M14 第 3 条「剪切板监听毫无作用」）：`CF_DIB` → `CF_DIBV5` 依次尝试，
  接受 `BI_RGB` 与 **`BI_BITFIELDS`** 两种压缩方式，后者按 DIB 里的**通道掩码**取色
  （现代截图工具 / 浏览器 / .NET 放上剪贴板的就是带掩码的 32bpp DIB；只认 `BI_RGB` 时会
  「每一步都成功、最后静默返回 null」，用户看到的就是监听毫无作用）。像素字节数按 DIB 头自己算
  （头 + 掩码 + 4 字节对齐的行），不依赖 `GlobalSize`（文档明确说它可能偏小/不准）。
  行序按 `biHeight` 正负判断（负 = 自上而下），因此 `_readI32` 必须真的做符号扩展。

- 多显示器与 Per-Monitor DPI V2 下坐标必须正确（截哪块屏就出哪块屏的图，不能截到缩放错位的区域）。
- 截屏前先隐藏本程序自己的窗口与托盘气泡，避免把 UI 拍进图里。
- 图片处理后统一转成 JPEG、长边 ≤ 1600px、质量 80，再算 `image_hash`。
- **手动框选题目区域默认关闭**（依据用户决策 6）。触发条件：当 AI 返回「未识别到题目」时，界面出现「手动框选重试」按钮，点开后才进入框选模式；该开关不写入设置、不常驻。
- **手机发起的识别在 Windows 端静默执行之外，还要「显示识别界面」**（用户反馈 15 + 本轮 12）：
  - 主机**自己**截屏 / 追加页 / 剪贴板 / 拖入（热键或托盘）→ **后台静默**：不把窗口弹到前台、不抢焦点；
    只有「必须让用户知道」的失败与前置条件（未选合集、未配置 AI、截屏失败、暂存区为空）才把窗口带回来。
    **「不抢焦点」包括截屏前后那次隐藏/恢复**（用户反馈 M15 第 3 条）：原来恢复用的是
    `ShowWindow(SW_SHOW)` + 无条件 `SetForegroundWindow`，等于每识别一次就把主窗口抢到前台 ——
    用悬浮球识别时用户正在别的应用里，观感就是「识别完界面自己跳出来」。现在恢复走
    `SetWindowPos(..., SWP_NOACTIVATE | SWP_SHOWWINDOW)`：**插回原来那个窗口下面**（藏之前记下
    `GW_HWNDPREV`），既不激活也不改层叠；只有**藏之前本来就是前台窗口**时才 `SetForegroundWindow` 还焦点。
  - **手机发起**的识别 → 主机把主窗口带到前台、回到主界面，并自动切到这次识别的会话（显示「识别中」→ 结果）。
  - 两个方向都把状态广播给已配对的手机（见 `protocol.md` 4.2）。
  - 本地识别的结果只体现在侧栏与托盘提示上（托盘 tooltip 会带「已暂存 N 页」）。

### 2.2 主窗口

**每个任务合集（collection）** 是识别记录的分组单位（用户需求 8）：

- Windows **每次打开都必须先进入一个合集**：不存在任何合集时先让用户命名新建，然后进入；选中状态记在本地设置（不参与同步），并通过 WS/`/info` 告知安卓端。
- 未选中合集时**不允许开始任何识别**（截屏 / 剪贴板 / 拖入 / 手机上传都会被拦下并提示），主界面被合集选择页挡住。
- 合集可新建、切换、重命名、删除（删除合集**不**级联删除其下记录，记录回到「全部记录」）。
  **删除有两个入口，都在二次确认之后才动手**：①「新建/选择任务合集」页每个合集行上的垃圾桶（M17 第 5 条）；
  ②**「切换任务合集」弹窗里每行的垃圾桶**（M19 第 2 条：顶栏合集药丸、托盘菜单、设置页「切换任务合集…」
  三个入口都走这个弹窗，它是**唯一随时可达**的合集入口 —— 原来只有启动时的选择页能删，用户进了主界面就再找不到）。
  确认框会写明「该合集下有 N 条识别记录；删除合集不会删掉这些记录」。
  删除是软删除（`deleted_at`）并生成同步 op —— **Windows 删了，安卓同步后不跟着没了**（M18 第 4 条反转，见 3.4）。

单一窗口，左侧会话列表、右侧当前会话内容：

- 左侧：**当前合集的**会话列表（按时间倒序），每项显示缩略图、时间、题目数量、页数（>1 时）、状态图标（分析中 / 完成 / 失败）；可切换查看「全部记录」。
- 右侧：当前会话的题目卡片，**纵向滚动**；一个会话多道题时依次排开。
- 底部/顶部导航：`← 上一次`、`下一次 →`、`回到本次`（语义见第 5 节）、题目计数（如 `第 3 / 7 条记录`）。
- 分析中：显示进度指示（已耗时秒数）与「取消」按钮；多页识别显示「N 页」。
- 顶部工具条：重新分析、复制全部、导出本次、导出本合集、删除本次。
- 顶部显示当前合集名（点击可切换）。
- **右上角不再显示配对状态药丸**（M21 第 2 条，用户在 M19 要求加、M20 修过、M21 又要求删）：
  顶栏那一枚「已配对设备：安卓设备 / 未配对」整个去掉（连「服务 8765 · 0 台」也没有了）。
  局域网服务端口、连接状态与已配对设备（含吊销）逐台列在**设置 → 连接设备**里，
  那里仍是唯一的配对状态来源。

### 2.2.1 多页识别（用户需求 4；M46 第 1 条合并成一个热键）

- **只有两个全局热键**（M46 第 1 条，与服务端 `server/lib/src/capture_flow.dart` 同一套语义）：
  - **截屏识别**（默认 `F8`）：不在多页模式 → 截一张屏立刻识别；**已经在多页模式**（暂存区非空）→
    **结束多页**，把已攒的图一起上传识别（**不再多截一张**）；
  - **多页模式**（默认 `F9`）：第一下进入多页并抓第 1 张，继续按逐页追加；
    **抓满上限（默认 6）时抓完第 6 张就自动上传识别**。
- 多页暂存仍是**内存里的暂存区**，每次识别结束即清空；达到上限（默认 6，可配 1..6）自动上传。
- **页数硬上限就是 6**（用户反馈 9：`kHardMaxPagesPerTask = 6`，本地设置也只能配到 6；超过会被服务端 `too_many_pages` 拒绝）。
- **暂存条只在真正攒页时出现**（用户反馈 5）：暂存 0 页时整条不渲染，主界面保持干净；攒页时显示「多页暂存：N/6 页」与「清空暂存区」。
- 多页作为一次请求发给 AI；**页序由模型自己纠正**（用户反馈 14：多页顺序可能乱，让 AI 识别完自行判断正确顺序），`sessions.image_hash` 存第一页，用户实际截取顺序存 `session_images`。
- **只有材料没有题目的页不能丢**（用户反馈 14）：这类页的内容作为所属题目的 `material` 一起送出。
- 托盘菜单提供同样两个动作（热键被其他程序占用时的兜底）。
- **悬浮球 / 悬浮窗**（M46 后仍然成立）：悬浮球单击 = 截屏识别（攒着页时即结束多页），长按/右键 = 加一页；
  悬浮窗的「多页识别 / 继续添加页」到上限时**不替用户上传**（提示点「结束并上传」），因为那是用户显式点的一次加页。

**设置页模块归属与底色**（用户反馈 3/4/5）：每个分类由若干**模块**组成，模块 = 一张卡片色底的圆角容器

### 2.4 托盘与生命周期

- 常驻托盘；关闭主窗口 = 隐藏到托盘，不退出；退出走托盘菜单。
- 托盘图标用**独立于应用程序图标**的品牌图（`assets/statusbar.ico`，由 `icon/Statusbar.png` 生成的多尺寸 ICO），由 `tool/make_icons.dart` 重新生成（用户反馈 8）；**与应用图标一样烘焙 22% 圆角**（用户反馈 1（本轮）：源图是白底不透明，四角 (254,254,254)，不裁角托盘里就是一个白方块）。
- **Windows 悬浮球**（用户反馈 11）：一个**原生分层窗口**（`WS_EX_LAYERED | TOPMOST | TOOLWINDOW | NOACTIVATE` 的 `WS_POPUP`，`UpdateLayeredWindow` 交付预乘 BGRA），不是在 Flutter 里画一个浮层。默认贴右边缘、垂直约 40%，可拖动、松手吸附最近边缘；8px 阈值区分点击与拖动；**单击 = 单图识别（攒页中则收尾识别）**、**左键长按 500ms 与右键完全等价 = 追加一页进入多页模式**（用户反馈 M16 第 2 条：判定改为在**松手时**按按住时长结算，不再靠 `SetTimer` / `WM_TIMER` —— 后者是队列里优先级最低的消息，用户按住不放时松手消息会先到，一次长按会被判成单击），与安卓端语义逐条一致；三种状态各有一张图（待识别 / 识别中 / 多页模式），截屏前自动隐藏。**多页手势全程静默**：追加页不会把主窗口带回前台（失败/前置条件缺失时才提示）。外观默认：**球 40 逻辑像素、整体不透明度 70%、描边开启（宽 4 / 不透明度 25%）**（M17 第 1 条）。开关与外观在「设置 → 悬浮球设置」，**默认关闭**（M14 第 4 条曾改为默认打开，M44 按用户要求改回默认关闭：出厂值 `kDefaultBallEnabled = false`，老库靠一次性迁移关掉）。
  - **渲染要缓存**（用户反馈 M14 第 4 条「打开后内存飙升」）：球图是固定素材，预乘后的 BGRA 按「状态 + 尺寸 + 描边 + 透明度」缓存（上限 8 条、尺寸一变即作废），切状态只做一次 `memcpy`。实测 300 次切换：不缓存 RSS 163.5 → 216.6 MB 且仍在涨，缓存后 159.2 → 175.0 MB 并停住。
- 托盘 tooltip 会带上「已暂存 N 页」（用户反馈 5/12：后台静默攒页时托盘是唯一可见提示）。
- 标题栏与窗口边框跟随主题深浅（用户反馈 7 + 本轮「Windows 也没改」）：**自己调 DWM**
  （`apps/desktop/lib/services/window_theme.dart`）——`DWMWA_USE_IMMERSIVE_DARK_MODE`（20，Win10 1809 回退 19）
  决定标题文字/系统图标明暗，Win11 22000+ 再用 `DWMWA_CAPTION_COLOR(35)` / `TEXT_COLOR(36)` / `BORDER_COLOR(34)`
  把标题栏底色对齐应用顶栏色（COLORREF 是 `0x00BBGGRR`）。
  **不能用 `windowManager.setBrightness`**：它把「应用要深色」与「系统当前是深色」做了 AND，
  系统浅色时永远是 no-op —— 这正是「切了深色标题栏不变」的老 bug；「跟随系统」时监听系统亮度变化重设。
- **应用数据目录默认在软件自己的目录下**（用户反馈 10）：`<exe 所在目录>\userdata`（数据库、图片、备份、导出、日志都在这一个目录里）。**不能叫 `data`**：Flutter 的 Windows release 产物本身就有 `<exe>\data\`（`app.so` / `flutter_assets` / `icudtl.dat`），混用会导致「清理 app 数据」把引擎删掉、程序起不来（实测踩过）。应用目录不可写（例如以管理员身份装进 `Program Files`）时退回系统数据目录；旧版本已写在 `%LOCALAPPDATA%` 下的库会被沿用，不会「升级后历史记录消失」。「设置 → 数据管理 → 数据位置」提供**「打开目录」**按钮直达资源管理器。
- ~~开机自启开关（写入注册表 `Run` 键，不使用计划任务）。~~ **M47 删除该功能与条款**：
  桌面端从未实现（全仓没有 `RegSetValue`），设置页里也没有这一项；契约里留着只会让人以为
  它存在。要开机自启就自己给 exe 建快捷方式放进「启动」文件夹。
  （独立产品 `server/` 的 `--background` 与它是两回事，见 `server/README.md`。）
- 首次运行时如有防火墙拦截，在 UI 上给出「允许局域网访问」的说明指引（不自动改防火墙规则，避免弹 UAC）。
- **托盘右键菜单有两个浮层开关**（M32 用户需求 4）：「显示悬浮球」「显示悬浮窗」，用勾选项表示当前状态（`MenuItem.checkbox`，Windows 上只有它才会画 `MF_CHECKED`）。

### 2.5 Windows 悬浮窗（M32 用户需求 1）

一个贴在桌面上的结果小窗：不切回主窗口就能看答案、接着识别、翻上一条/下一条。

- **实现方式**：Dart 侧把「状态 → 一帧像素」离屏渲染好（`services/float_window_view.dart` 的纯函数布局 +
  `renderFloatWindow` → 预乘 BGRA），交给一个**原生分层窗口**（`services/float_window.dart`，
  `WS_EX_LAYERED | TOOLWINDOW | NOACTIVATE`，可选 `TOPMOST`）用 `UpdateLayeredWindow` 合成。
  **不为它再起一个 Flutter 引擎**（理由见 `DECISIONS.md`：多引擎要重注册一堆插件，
  而 `window_manager` / `tray_manager` 都是单窗口假设）。
- **题目内容 = 文本为主 + 明显的题目轮廓**（M34 第 8 条，**取代** M33 的离屏渲染）：
  内容区由 `services/float_window_content.dart` 用 `TextPainter` **直接排版**成图元
  （`layoutQuestionContent`），每题画出圆角卡片轮廓 + 题号徽标 + 题型与把握率 +
  命中选项标色 + 答案块/解析块底色条；排版结果按「会话 + 题目指纹 + 宽度 + 字号 +
  极简 + 配色 + 明暗」缓存（`FloatNode.painter` 挂住排好的 `TextPainter`），
  滚动/悬停只重新合成、不重排。
  历史：M32 手画（公式退化成纯文本）→ M33 把主界面 `QuestionCard` 离屏渲成位图
  （格式一致，但每帧都要跑整条 widget → 位图管线 + 贴一张高图，**实测悬浮窗明显卡顿**）
  → M34 回到文本直排。**代价（明确接受）**：公式按 LaTeX 源码显示，不再由 `MathText` 排版。
- **悬浮窗不排版公式，而且必须在设置页里如实写出来**（M46 第 2 条，用户要求「声明悬浮窗不支持显示公式」）：
  「设置 → 悬浮窗设置」的页面说明与显示模式开关的 ⓘ 里都写明公式按 LaTeX 源码显示、
  要看排版好的公式请回主窗口；两种显示模式（默认模式 / 详细解析模式）一视同仁。
- **图层列表同时是命中区**：`FloatFrame.hitRegions` 就是那些带 id 的按钮矩形，原生按窗口内坐标查表
  → 不存在「画的位置」与「能点的位置」两份真相。
- **开关**：默认**关闭**（用户需求 1.12），开启后记住状态；设置页与托盘菜单都能开；
  **托盘菜单文字随状态变**（显示悬浮窗 / 隐藏悬浮窗，M33 第 2 条）。
- **置顶**（1.1）：默认置顶，可在设置里关掉。
- **拖动 / 锁定**（1.2、1.6 + M33 第 4 条）：没有标题栏，**未锁定时只有顶部第一栏按住可以拖动**
  （内容区要留给滚动与点选，整窗可拖会误触）；锁定后忽略位移（点击按钮始终有效）。
  默认位置是**屏幕右侧、不贴边**（距右 24 逻辑像素）；设置里有「恢复默认位置」。
- **透明度 / 显示比例**（1.3 + M33 第 15 条）：整体透明度默认 **90%**（渲染时乘 alpha）；
  显示比例 0.5×–3.0× **无极调节**，窗口宽 = 该外观的基准宽 × 比例、高 = 宽 ÷ 宽高比。
- **外观三选一**（M33 第 1/15 条）：**删掉了自由拉伸**，只在
  **标准（竖屏 9:20，基准 342×760）**、**加长（竖屏 9:30，基准 270×900）**、
  **横向（20:9，基准 560×252）** 之间选，默认 **标准竖屏 9:20**。
  每种外观自带基准宽度（沿用横向的 560 时 9:20 会高到 1244 逻辑像素、放不下 1000 高的桌面）。
- **窗内字符大小只在设置页调**（1.4 + M34 第 7 条）：窗内**不再有** `A−`/`A＋` 两个按钮；
  「重新识别」对当前这一次重新调用 AI（`AnalysisWorkflow.retrySession`，强制不走缓存）。
- **顶部第一模块**（1.7 + M33 第 3 条 + M34 第 2/3 条）：左侧上下两行是「第 N/M 次识别」与识别时间
  （**不再显示「共 X 题 / Y 张图片」**）；右侧是一排**图标按钮**（不显示文字，**鼠标悬停出提示气泡**），
  顺序：下一条 · 上一条 · 重新识别 · 极简模式 · 锁定位置
  （没有上一条或下一条时对应按钮置灰且不可点，但**仍然画出来**）。窗宽不足时自动换行。
  图标字形与文字都**按行高在按钮里垂直居中**（M34 实测：只按 `rect.top` 画会贴上沿，看着像按钮坏了）。
- **题号行**：排序序号 + 题号徽标 + 题型 + `把握 N%`。序号是「本次识别的第几题」，
  **不带尾随点号**（M33 第 8 条：用户澄清「题号不带 `1.` 说的只是 `.`，不是不显示」）；
  悬浮窗总是显示把握率（第 13 条），主界面仍按 `ai-contract` §6 在把握 100% 时省略。
- **正常 / 极简模式**（M33 第 7/12 条）：极简模式 = **只看题目答案模式** ——
  选项只保留命中的那些、不渲染解析与阅读材料；选择/多选/判断的答案本来就标在选项上，
  因此**不会再另起一行写「答案：X」**；填空与主观题照旧显示答案框。
  AI 没识别出答案时**保留全部选项**（否则用户连题都看不懂）。
- **底部两个识别按钮**（1.9 + M34 第 4 条）：默认是「识别一张」（截一张图直接识别）与「多页识别」
  （进入多页模式并加第一张）。进入多页后变成「结束并上传」「继续添加页（N/上限）」
  「取消多页」：页数到上限时「继续添加页」**变灰不可点**，只能点结束上传
  （这一点与热键路径不同：热键攒到上限会自动上传，因为热键没有按钮可点）；
  「取消多页」丢掉暂存页、退出多页模式、不上传。
  **尺寸适度**（一行文字那么高 + 上下 8 逻辑像素留白，圆角沿用主界面的 `AppRadius.control`），
  文字垂直居中；**不做悬停放大**（M34 试过 macOS Dock 式放大，用户否掉：「太奇怪」）。
- **识别中**（1.10 + M33 第 5/10 条）：提示贴在**内容区下部**（不是正中），文案
  「识别进行中…（本次 N 张图片）」；**底部两个按钮不做禁用**（忙碌时点它会由
  `CaptureCoordinator` 自己提示「正在分析上一张」），**也不再提供「取消识别」**
  （M33 明确删掉那条设定）。识别结束后自动跳到**最新**那一次的界面（`index = 0`、滚动归零）。
- **配色与明暗**（M33 第 9 条 + 1.11 + M34 第 6 条）：6 套配色（纯净白默认 / 薄荷绿 / 天空蓝 / 丁香紫 / 暖沙 / 樱粉）
  都是**浅色系**，只决定色系；明暗由「明暗模式（跟随软件设置 / 明亮 / 深色）」决定，两者正交。
  **纯净白的种子色必须是中性色**（M33 错填了绿色，等于给「纯净白」套了薄荷绿）；
  题目卡片里的标绿/标黄仍按 `ai-contract` §5 走（那是信息，不是装饰）。
- **截屏时隐藏**：与悬浮球一样挂进 `overlayHiders`，识别出来的图里不会有这个窗。
- **鼠标**：顶部第一栏拖动、任意处点击按钮、滚轮滚动内容、悬停出提示、点击空白处无动作。

## 3. Android 端功能

### 3.1 悬浮球

- 识别模块总开关（用户需求 11）**默认关闭**；关闭时悬浮球不显示、截屏/上传入口不可用。
- **关掉悬浮球（或识别模块总开关）= 截屏会话一并结束**（M47 用户实测反馈「关闭悬浮球后，屏幕共享未自动终止」）：
  悬浮球是截屏的唯一入口，关掉它就要停掉常驻的截屏前台服务（`CaptureService.stop` → `releaseCapture()`），
  释放 `MediaProjection`/`VirtualDisplay`/`ImageReader`，系统那条「正在共享屏幕」的提示随之消失；
  下次要用时 `availability()` 会报不可用 → 重新弹一次系统授权框（与其他「会话失效」路径一致，不静默失败）。
- **开关旁边必须写明这条路径的耗时代价**（M19 第 3 条）：
  「受限于网络延迟与 API 端响应，可能识别时间过长，不建议开启。」（`kRecognitionSlowNote`，黄色警示条）。
  这条路径是「手机截屏 → 局域网 → 电脑 → 第三方 AI → 再传回来」，比本机识别多绕两跳；
  说明只是**知情提示**，不拦人、不改默认值 —— 设置首页的开关下方与「识别模块设置」二级页顶部各显示一次。
- 开启后悬浮球为侧边可拖动的半透明圆形按钮，松手后吸附到最近的左/右边缘，垂直位置保留；**默认初始位置贴右侧边缘、垂直约屏幕 40%**（用户反馈 14）。
- **单击 = 截一张图直接上传分析**（单图）。
- **长按 = 一题多页模式**（用户需求 11；M49 与 Windows 端热键对齐）：
  - 第一次长按：截第 1 页并**立即上传该页**（页 hash 记入本地暂存），进入多页模式；
  - 继续长按：依次追加第 2、3… 页，最多 `multiPageLimit`（默认 6）页，到达上限时提示「已达上限」并**自动**创建多页任务上传识别、退出多页模式；
  - **手动停止**：多页模式下**下一次短按**即为结束 —— **只提交已经截好的页**，**不再补截一张**
    （桌面端 F8「结束多页并上传已抓的图」也是这个语义，两端手势一致；页数严格等于长按次数）。
  - 界面上对这套手势的说明必须写清顺序（用户反馈 10）：「长按截第 1 张（松手即完成一页）→ 再长按截第 2 张 → 以此类推 → 最后短按收尾」，
    并写明「收尾的短按只提交已截好的页，不会再多截一张；抓满上限会自动提交」。
- **采集与识别全程静默**（用户反馈 15）：截屏后不跳转页面、不把主界面拉到前台、不弹结果页；进度与结果只反映在「当前任务」页与常驻通知里。
- **过程提示不排队**（M49 用户反馈「识别期间攒下的提示，回到应用后一个一个跳出来」）：
  应用内提示是**瞬时**反馈 —— 人在别的应用里（悬浮球手势期间）时**不入队**（那一侧的反馈由系统 Toast 承担，
  用户当场就能看到）；在前台时只保留**最新一条**（丢掉积压的旧提示）；回到前台再清一次队列。
  系统 Toast 同理：新的一条顶掉正在显示的那条，不按条排队（`Toast.makeText().show()` 本身会排队）。
- 拖动时不触发截屏：以移动距离阈值（建议 8dp）区分点击、长按与拖动。
- 截屏前**必须先隐藏悬浮球自身**，等待约 250ms 再取帧，截完恢复，避免球被拍进图里。
- 悬浮窗权限（`SYSTEM_ALERT_WINDOW`）未授予时，App 显示引导页直接跳系统设置。
- 悬浮球开关、透明度、大小、截屏方式与权限引导都在 **设置 → 识别模块设置** 二级页里（用户需求 11）。

### 3.1.1 首次打开与配对（用户反馈 12）

- 首次打开**不自动调起相机、不自动申请相机权限**：未配对时先显示说明与「开始使用」入口。
- 用户点「开始使用」后才申请相机权限；被拒要给出明确提示与重试入口，授权成功后才启动扫码。
- 配对页是**三个并列模块**（用户反馈 16）：**方式一：扫码**（只放扫码/相机相关）、**方式二：粘贴配对链接**（独立模块，从方式一里搬出来）、**方式三：手动输入**。
- 手动输入 `IP:端口 + 配对码` 与「粘贴配对链接」两个入口始终可用（不依赖相机）。

### 3.1.2 界面与主题（用户反馈 7/11 + 本轮 11 + M13）

- 状态栏/导航栏的底色与图标明暗**跟随当前主题**，切换主题**立即生效**。三层保障，缺一层都会在部分机器上失效：
  1. **底色由 App 自己画**（M13 新增，最关键）：Android 15（API 35）起 Flutter 引擎
     **不再设状态栏底色**（引擎产物 `PlatformPlugin` 里 `if (SDK_INT >= 35) 跳过 window.setStatusBarColor`，
     已反编译核实），平台 15 起也规定状态栏区域显示的就是应用自己画的内容。
     所以 `ThemedSystemUi` 在顶部安全区（`MediaQuery.padding.top`）画一条**与应用顶栏同色**的条带
     （`system-ui-status-strip`，不吞触摸事件），这条才是底色真正跟随主题的保证。
     M10（透明底 + 图标明暗）与 M11（显式配色）在这类机器上都不可能生效 —— 用户连报两轮的就是它。
  2. **图标明暗走自家 Kotlin 桥**（`quizsync/system_ui` → `SystemUiBridge`）：用官方推荐、未废弃的
     `WindowInsetsControllerCompat.isAppearanceLightStatusBars/isAppearanceLightNavigationBars`
     （Flutter 引擎内部用的也是它）。API < 35 时同时设 `window.statusBarColor/navigationBarColor`
     与 `isStatusBarContrastEnforced = false`；宿主在 `onResume` / 窗口获焦时**按缓存的样式重贴一次**
     —— Android 会重置这些窗口标志（引擎的 `enableEdgeToEdge()` 就把 visibility 清成 0），
     而 Flutter 侧以为「已经下发过」不会重发。
  3. **声明式兜底**：`AnnotatedRegion` + `AppBarTheme.systemOverlayStyle` 用同一份样式，
     负责按页面/路由自动切换；`reapplySystemUiOverlayStyle` 在首帧后 / 主题切换 / `resumed` /
     平台亮度变化时**直接经平台通道重发**，绕开 Flutter 的 `_latestStyle` 缓存。
     设置页「关于」里会显示当前生效的系统栏样式，便于区分「App 没下发」与「ROM 忽略」。
- 启动窗口（`LaunchTheme` / `NormalTheme`）的系统栏底色改为**透明**，只声明图标明暗：
  原来不写这几项时平台默认底色是黑色，Android 15+ 上引擎又不会再设，用户看到的就是一直黑着的状态栏。
- 权限引导只讲「需要什么权限、为什么」，**不点名任何具体系统或品牌**（旧文案里的国产 ROM 名单已过时，删除）。


### 3.2 截屏

主路径（用户已定）：常驻前台服务复用同一个 MediaProjection 会话。

- 首次使用弹一次系统授权框；授权后服务保持会话常驻，之后点击悬浮球不再弹窗。
- 前台服务声明 `foregroundServiceType="mediaProjection"`，并显示常驻通知（这是 Android 14 的硬性要求，也是会话存活的前提）。
- 常量约束：一次授权 = 一个 VirtualDisplay 会话，`createVirtualDisplay` 每个会话只能调一次；必须注册 `MediaProjection.Callback` 处理 `onStop`。
- 会话失效（锁屏、系统回收、用户停止录制、权限被撤销）→ 检测到后清除状态，在下次点击时提示并引导重新授权。
- 截到的帧写入 JPEG 字节，经 MethodChannel 交给 Dart 层，**Dart 层不接触 MediaProjection API**。

备选路径：设置项里可切换到 `AccessibilityService.takeScreenshot()`（API 30+）。在低于 API 30 或用户拒绝无障碍权限时不可用，此时回落到主路径。

降级通路：当截图返回全黑或取帧失败（通常是对端应用设置了 `FLAG_SECURE`）→ 提示「该应用禁止截屏」，并提供「从相册选图」按钮走同样的分析链路。**不实现任何绕过**。

### 3.3 结果显示

- **本机发起**的识别全程**静默**（用户反馈 15 + 本轮 12）：不跳「识别中」页、不自动跳结果页、**不切换底部标签**、不把 App 拉到前台；在后台时发通知，点通知才进结果页。
- **主机（Windows）发起**的识别则要**显示出来**（本轮 12）：
  - 主机开始识别（`task_update` = `analyzing`）→ 当前任务页显示「N 张图片识别中…」；
  - 结果到达（`task_result`）→ **自动进入本次识别的结果页**（仅在 App 处于前台时自动跳，且只跳一次；后台到达的结果会在回到前台时补跳）；
  - **当前任务页已经显示着上一轮结果时**，下一轮识别不覆盖它：页面**顶部出现悬浮横幅**「N 张图片识别中…」，旧结果继续显示在下方；完成后横幅显示「识别完成」并自动进入新一轮的结果页。
  - **停在结果页上也看得见**（用户反馈 M16 第 3 条）：用户在**结果页**（不是当前任务页）时，同样在页顶浮起「电脑正在识别中…（N 张图片）」，出结果时变成「识别完成，正在打开新结果…」，随后新结果页被推上来。判定条件与当前任务页一致 —— 只有**电脑自己发起**的识别才出现（本机悬浮球/相册识别一律静默，见上面的「全程静默」），而且**正在看的那次**自己的「重新生成」不算新的一轮。跳页仍然只有一个出口（当前任务页消费 `autoOpenResult` 后 push，结果页只负责显示，不重复推页）。
    **它必须画在题目上面**（用户反馈 M18 第 3 条）：结果页的 `Stack` 里浮层是**最后一个**孩子（`Stack` 后画的在上层），底色**不透明度 85%**（只淡化卡片底色，文案与图标保持完全不透明，压在题目上才读得清）。
- **当前任务页就是「Windows 结果显示器」**（用户反馈 3）：只显示与电脑的连接状态和主机任务的进度/结果，**不出现识别模块的开关、权限提示或任何本机采集相关的提示**（这些入口只在「设置 → 识别模块」里）。连接状态只由页面顶部那张卡显示一次（本轮 16：下面不再重复显示连接信息）。
- **一次识别的全部题目在同一页纵向显示**，不再会话内分页（用户需求 1）。
- 结果页底部导航是 **上一次识别 / 下一次识别**（在**会话之间**跳转，用户需求 1），顶部显示「第 N/M 次识别 · 时间」。
- 结果页与 Windows 端同构：题目卡片纵向列表、正确答案标绿（AI 不确定时标黄，见 4.3）、字号可调（`A-` / `A+`）、主题跟随（见第 4 节）。
- 结果页提供「重新生成」：请求主机按同一页序重跑一次（用户需求 7）。
- 结果页顶部显示来源（本机截屏 / Windows 端分析）与时间。

### 3.4 底部导航、历史与设置

- 底部三标签：**当前任务 / 历史记录 / 设置**，默认打开**当前任务**（用户需求 6）。
- **当前任务**：只有两件事 —— ① 与电脑的连接状态（已连接但未开始任务 / 未连接电脑 / 主机未选合集，各给一句文案）；② 主机任务的进度与结果。主机开始识别后本页**自动刷新**：未完成显示「N 张图片识别中…」（页数取自 `task_update.image_count`），完成后自动显示答案，可点击「重新生成」（用户需求 7 / 用户反馈 2）。
  - **每秒轮询主机状态兜底**（用户反馈 M15 第 4 条）：除了 WS 推送，安卓端在配对成功且 App 在前台时**每 1 秒**问一次
    `GET /api/v1/tasks/active`（`protocol.md` 3.4.1），把结果拼成与 WS **完全相同的消息**交给同一套落地逻辑
    （识别中 → 出结果自动进本次结果页 → 页面已显示上一轮结果时先出顶部悬浮横幅；本机自己发起的识别保持静默）。
    这样即使一条推送都没收到，界面也会自己跟上。**状态没变就一条通知都不发**（不重建列表），
    失败只把状态行改成「电脑未连接」、不弹提示；`revoked` 与 WS 一样要求重新配对。
  - **但只要前台就一定要刷新**（用户反馈 M17 第 4 条）：轮询器除了「主机上报的指纹变没变」，
    还会比对**界面当前展示的任务签名**；界面停在别的任务上（上一次通知丢了 / 被后台吞了）就补发一次，
    界面为空（用户点过「忽略」）则不补发。判定进终结态时**只看状态与会话 id，不比页数**
    （否则会把同一条结果再通知一次、重复跳页）。
  - **主机本地改动 1 秒内同步到手机**（用户反馈 M17 第 5 条）：`/tasks/active` 顺带回报主机
    **本地 ops 水位** `ops_lamport`；水位涨了（Windows 上改题目等）就做一次
    **只拉不推**的同步（`pullFromPeer`，不 drain 离线队列、不 push）。第一次只建立基线。
    —— 这是「Windows 有什么安卓就有什么」的兜底通路；WS 通的时候还会收到 `ops` 消息。
  - **主机的分类（合集）必须同步到手机**（用户反馈 M18 第 4 条）：同一个端点还回报主机
    **当前活跃合集列表** `collections`；轮询**第一次观测就**把这份列表**镜像**进本地库
    （`mirrorCollections`：只增改、不删、不产生同步 op），于是主机新建/改名的合集在手机
    「历史记录」里 1 秒内出现，主机识别的记录也不会再被算进「未分类」。这份列表是
    **想要的结果**本身，不依赖 `ops_lamport` 这类间接触发信号（旧做法会漏，且漏了不自愈）。
  - **删除合集的方向是不对称的**（用户反馈 M18 第 4 条，**修改** M17 第 5 条）：
    Windows 删合集 → **手机本地那个分组保留**（远端删除 op 不回写 `deleted_at`，
    只有用户明确要求「windows 端删除后安卓端不再同步跟着删除」）；
    手机删合集（见下条）→ 本机软删除 + 生成 op **照常同步给主机**。
- **历史记录**：先按**合集**分组（未归属的归入「未分类」），点进合集看到该合集的识别记录，再点进记录看题目；支持删除（二次确认，软删除并同步，用户需求 13）。**安卓端不再提供任何导出 / 分享入口**（本轮 2：导出统一在 Windows 端做，那边弹「另存为」可选位置）。
  - **合集也能在手机上删除**（用户反馈 M18 第 2 条）：**长按**合集分组进入多选模式
    （顶部出现「已选 N 个合集 · 取消 · 删除」，点条目 = 切换选中），删除走二次确认；
    **不级联删记录**（合集下的记录回到「未分类」，与 Windows 端一致），
    「未分类」不是合集、不可选。
- 数据来自本地库，Windows 不在线时也能看；未成功分析完的会话显示状态与重试按钮。
- 设置：服务器地址（扫码配对 / 手动输入）、**主题模式（跟随系统 / 浅色 / 深色，不再提供配色选择）**、字号、**识别模块总开关 + 二级页「识别模块设置」**（截屏方式切换、悬浮球开关与透明度/大小、权限引导）、解除配对、关于（**M17 第 2/3 条：桌面图标名 = 中文「AI 双端搜题」，关于页写明项目地址 `https://github.com/iop666/QuizSyncAI`，点一下复制地址**；**M18 第 1 条：版本只写版本号、不再显示「（构建 N）」**；**M47：版本与桌面端统一为 `v1.1.0`**）。**不再提供「图片缓存上限」设置项**（M14 第 7 条，见 §4.2.1）。
- 发起识别前必须确认主机已选中合集；没有则提示「请先在电脑上选择任务合集」并阻止上传（可在手机上直接切换主机合集，用户需求 12）。

## 4. 显示规则（两端一致）

### 4.1 字号

- 范围 12–32（单位 sp / px 按平台等价值），步进 1，默认 16。
- 设置持久化在本地，两端各自独立（用户已定：不强制同步）。
- Windows 额外支持 `Ctrl + 鼠标滚轮` 实时缩放；Android 支持双指捏合。
- **界面整体缩放**（仅 Windows，用户反馈 9/7）：**只提供固定档位下拉框** 50% / 75% / 100% / 125% / 150% / 175% / 200% / 225% / 250% / 275% / 300%，默认 100%（`kUiScalePresets`）。对整个界面（含设置页与弹窗）等比缩放；选中后**自动按同比例调整窗口边界**（窗口物理尺寸 × 新旧缩放比，并夹在当前显示器工作区内），保证缩放前后可见的内容范围基本一致。**不提供进度条**。
  用户反馈 8 的三条补正：① 改缩放前先 `unmaximize`（最大化时系统会忽略 `setBounds`，看起来"边框完全没动"）；
  ② **窗口最小尺寸也按缩放比例放开**（`kBaseMinimumWindowSize` × scale，夹到工作区）—— 否则缩到 50% 时窗口被
  860×520 卡住；③ **启动时按已保存的缩放摆窗口**（`applyStoredUiScaleToWindow`），「上次用的是 150%」这次打开时
  窗口就是 150% 的大小。窗口尺寸的请求值与回读值都会写进日志，便于确认"边框到底跟没跟住"。
  **但「窗口小了」并不等于「界面铺满了」**（用户反馈 M14 第 1 条，第 2 次修）：缩放是「虚拟画布 + 等比缩小」
  实现的，根节点给下来的**紧约束**会把 `Transform.scale` 里的 `SizedBox(虚拟尺寸)` 夹回窗口尺寸 —— 界面于是按
  窗口尺寸布局、再被缩小到一半，只画在左上角，右边/下边留下一块没有任何 widget 覆盖的区域（引擎清屏色，深色主题下
  就是「那片黑」）。所以虚拟画布必须用 `OverflowBox`（min/max = 窗口尺寸 / scale）撑开，绘制结果才铺满窗口。
  `apps/desktop/test/ui_scale_test.dart` 直接断言「铺满子块缩放后的全局矩形 == 窗口矩形」。
- **题目字重**（仅 Windows，用户反馈 1）：300–700（默认 500），走 MiSans 可变字体的 `wght` 轴；界面字体族也只在 Windows 端换成 MiSans，安卓端保持系统字体。

### 4.2 主题

- 三态：跟随系统 / 浅色 / 深色（用户需求 10）。
- 两端各自独立设置；**两端都不再提供主题配色（accent）选择**，统一使用品牌绿种子色。
- **系统栏/标题栏跟随主题**（用户反馈 7）：Windows 标题栏由 DWM 深浅色跟随；Android 状态栏与导航栏的底色、图标明暗跟随当前主题。

### 4.2.1 本地图片缓存上限（用户需求 5 + 用户反馈 M14 第 7 条）

- **Windows**：本地保存的截取图片默认**最多 60 张**，可在设置里改（0 / 「不设限」= 不清理）。超出时删除**最旧的**本地文件并把 `images.local_path` 置 NULL；文本结果与元数据永久保留。
- **Android**：**固定只保留最近 20 张**（`kAndroidLocalImageLimit = 20`），**不再提供缓存上限设置项**（用户反馈 M14 第 7 条：用户明确要求取消这个选项）。清理规则同上：删最旧的原图，文本结果与元数据不动。
- **手机上传的图片与 Windows 本机截图放在同一个目录**（用户反馈 M14 第 7 条）：都写进 `<数据目录>\images`，用户打开「设置 → 数据管理 → 打开目录」时，两端产生的图片都在里面（此前手机上传走的是另一个 `server-images` 目录）。
- **手机上传的图必须写 `images.local_path`**（用户反馈 M15 第 2 条）：服务端收到上传后先落盘、再把刚落盘的路径写进这一列
  （原来在写文件之后又查了一次库，而写文件不建 `images` 行 → 拿到的永远是 null，于是手机传来的记录在 Windows 主界面
  **只有占位图标、没有缩略图**，结果页与「重新分析」也找不到原图）。重传同一张图时会顺带把历史上丢了路径的记录补上。
  客户端（Windows 主界面缩略图）另外保留一条兜底：`local_path` 为空或文件不在时，回落到约定路径 `<数据目录>/images/<hash>.jpg`。
- 两端各自独立设置，互不影响。

### 4.2.2 不完整题目与 AI 猜测（用户需求 2/3）

- `incomplete == true` → 整个题目外框**黄色**，顶部黄底横幅「题目不全」。
- `answerGuessed == true` → 黄色徽标「AI 猜测答案」，答案区标题追加「（AI 猜测）」。
- 只有答案、没有题干的条目**不显示**（丢弃，不编造题干）。
- 有题干但选项不全时仍然显示，答案由 AI 按题意推断并注明是猜测。
- 题目标题 = **排序序号 + 题号徽标**（例 `3.` 外面、`第 12 题` 在徽标里）；识别不到题号时徽标显示 `第 <序号> 题`。导出文件仍用纯文本 `3. 第 12 题`（`Question.displayTitle`）。
  用户反馈 7：序号是「本次识别的第几题」、题号是 AI 从图里读到的数字，含义不同，**序号放在题号徽标的外面前面**，不要挤进同一个徽标里被读成一个数字（两端一致）。
- 具体字段与规范化规则见 `ai-contract.md` 4.2 与第 3 节表格。

### 4.2.3 阅读材料与结构化主观题（用户反馈 15）

- **阅读类题目**（阅读理解 / 完形填空 / 材料题 / 资料分析）：AI 把文章、段落、图表文字完整写进 `material`，`stem` 只写问题本身；同一份材料下的每道小题都带同一份 `material`。
- 端侧（两端共用 `QuestionCard`）：`material` 非空时在题干上方渲染**「阅读材料（N 行，点击展开）」面板，默认折叠**，点标题条展开/收起；`material` 为空时完全不渲染。
- **主观题答案必须结构化**：AI 的 `answer.text` 分点、换行、带 ①②③ / 1. 序号；端侧对多行答案**按行渲染**（没有序号的行走项目符号），单行答案保持原样。
- 导出 Markdown 时 `material` 以引用块形式放在题干之前。
- **正文按结构化内容渲染**（M21 第 1 条，两端共用 `MathText`）—— 题干、材料、选项、解析、答案五处同一套规则：
  - **公式分块**：`$$…$$` 与 `\[…\]` 一律独占一行；**超过当前宽度可容纳字符数**的行内公式也搬成块级
    （阈值按 `宽度 / 11` 估算并钳在 24–96 字符），块级可横向滚动，再长也不会被裁掉或把整段挤出屏幕；
    能留在句子里的行内公式用 `MathStyle.text`（display 风格会把行高撑得忽高忽低）。
  - **化学式小标**：AI 在题干/材料/解析里几乎不写 LaTeX，`ZnCO3`、`Fe2O3`、`H2O2`、`Fe2+`、`Cu2+`
    这类裸写法要按元素符号切分渲染 —— 原子个数下沉成下标、电荷上浮成上标（`ZnCO₃`、`Fe₂O₃`、`Fe²⁺`）。
    判定用元素符号白名单 + 「至少一个数字或电荷」，`pH`、`MPa`、`Kp`、`2026` 这些不能被误判。
    **电子 `e-` 也要上标**（M22）：离子方程式里的 `Cu²⁺ + 2e⁻` 写成 `Cu2+ + 2e-`（`e` 是小写、
    后面是普通连字符），`2` 是系数保持正文字号、只有负号上浮。
    **同一行里的运算符绝不能跟着上标**：`2H₂O - 4e⁻`（以及不留空格的 `2H2O-4e-`）里，
    `H2O` 后面的 `-` 是减号、`O2+4H+` 里的 `+` 是加号，**只有紧跟元素且不接数字/字母的那个符号**
    才是电荷；`e-mail`、`1e-5` 这类也不许误伤。
  - **表格**：材料里的表格要画成**真表格**（带边框、可横向滚动），不能挤成一行。两种来源都认：
    空格对齐块（`光照强度/klx    0    2    4    6    8`）与 Markdown 竖线表（后者按表头样式渲染）。
  - **化学平衡箭头**：`⇌` 用 KaTeX 字形画（随包 MiSans 里没有这个字，不能指望系统字体回退）。
- **公式渲染认四种定界符**（M20 第 2 条）：`$$…$$` 与 `\[…\]` 作独立公式、`$…$` 与 `\(…\)` 作行内公式，
  两端共用 `MathText`。prompt 要求写 `$…$`，但模型对物理题常吐 LaTeX 原生的 `\(…\)`（用户真实库里
  `\(m_A = 1\,\mathrm{kg}\)` 与 `\(E_p=\frac{16}{3}\,\mathrm{J}\)` 这类就是它），只认 `$` 会让整段公式连
  定界符一起被当普通文字画出来。解析失败仍按原样回退等宽显示源码（不白屏）。
- 多页识别里**只有材料没有题目的页不能丢**（用户反馈 14）：该页内容进入所属题目的 `material`；多页页序错乱时由模型自行判断正确顺序后再输出。

### 4.3 正确答案标绿（核心规则，逐字实现）

数据来源**只有** `answer` 结构化字段（见 `ai-contract.md`），不得从解析文本里搜索答案。

| 题型 | 标绿对象 |
|---|---|
| 单选（single） | `answer.choice` 中的那一项的选项行 |
| 多选（multi） | `answer.choice` 中**所有**命中项的选项行 |
| 判断（judge） | 「对 / 错」两个按钮中，与 `answer.choice` 匹配的那个 |
| 填空 / 主观（blank / subjective） | 无选项，把 `answer.text` 在「答案」区块用绿色文字 + 浅绿底显示 |

选项行标绿样式（两端一致）：
- 浅色主题：文字 `#16A34A`，背景 `#DCFCE7`，左侧 4px 竖条 `#16A34A`，行尾 ✓ 图标。
- 深色主题：文字 `#4ADE80`，背景 `#14351F`，左侧 4px 竖条 `#4ADE80`，行尾 ✓ 图标。
- 加 ✓ 图标是刻意的：**颜色不能是唯一的信息通道**，兼顾色觉障碍用户。
- 深色主题必须用上面单独的绿色值，不能复用浅色主题的 `#16A34A`（对比度不足）。

边界情形：
- `answer.choice` 为空但 `options` 非空 → **不标绿**，显示「未识别出答案」，并标记需复核。
- `answer` 与 `options` 的 label 对不上（AI 返回了不存在的选项）→ 不标绿，记入 `warnings` 并提示。
- 用户手动改过答案 → 用用户的值标绿，并在卡片上显示「已人工修改」标记（与 AI 答案区分）。

**AI 不确定时不用绿色（用户反馈 13）**：当 `need_review == true` 或 `confidence < 0.6`
（`HighlightResult.needsReview`）时，命中的选项行与「答案」区块改用**黄色**：

- 浅色主题：文字 `#D97706`，背景 `#FEF3C7`；深色主题：文字 `#FBBF24`，背景 `#322712`。
- 行尾图标同时从 ✓ 换成 `help_outline`，与「可信答案」在视觉和信息通道上都区分开。
- 绿色专留给「AI 有把握」的答案；黄色与 4.4 的复核徽标同色系，语义一致。

### 4.4 置信度提示

- `confidence < 0.6` 或 `need_review == true` → 卡片顶部显示黄色徽标「AI 不确定，建议复核」。
- 全应用范围内必须存在一处常驻免责声明：「答案由 AI 生成，仅供参考」。

### 4.5 提示与长文本换行（用户反馈 9）

- AI 给的 `warnings`（例如「答案为图中猜测答案，且材料…」）在解析区下方渲染成**一行一块的提示块**，
  正文必须自动换行（`Expanded` + `softWrap`），**不能**做成不换行的横向药丸 —— 否则一句长提示会直接顶出
  屏幕边界（安卓端实测）。提示正文用比底色更深的颜色（`HighlightColors.warnText`：浅色 `#92400E` /
  深色 `#FCD34D`），保证在浅黄底上可读。
- 安卓「当前任务」页的「识别完成」答案是**受约束的等宽块**（题目与答案各占一半、`softWrap`），
  多行结构化答案换行显示，不横向溢出。

## 5. 历史记录与导航（用户已定语义）

- **一次识别 = 一条记录（会话）**。历史列表即会话列表。
- 识别记录归属**任务合集**：Windows 端只看当前合集的记录（可切「全部记录」），安卓端历史先按合集分组再进记录（用户需求 8）。
- 「上一次 / 下一次 / 回到本次」在**会话之间**跳转：
  - 「上一次」= 时间上更早的那条会话（更旧的）。
  - 「下一次」= 时间上更晚的那条会话（更新的）。
  - 「回到本次」= 跳回**最近一次识别**的会话（列表第一条），无论当前在哪。
- 一个会话里识别出多道题时，**在同一个页面纵向滚动显示**，不拆成多条记录；安卓端同样如此（用户需求 1）。
- 会话内多题若超过一屏，提供题内快速跳转（右侧题号锚点或小圆点），但默认只需上下滚动。
- 翻到旧会话时不应把它当成"新的当前会话"——「本次」始终指向最新那条。
- 搜索：对题干与解析做全文检索（Windows 用 FTS5，Android 用 LIKE 或 FTS4 均可，属本地功能，不强求实现一致）。
- **删除**：两端都可删除历史记录（软删除 + 同步，二次确认，用户需求 13）；空状态要区分「还没有记录」与「搜索没有匹配」。
- **合集导出**（用户需求 9）：选择一个合集一键导出可读文件（Markdown + JSON），**按识别顺序排序**；**只在 Windows 端提供**（本轮 2：安卓端的导出/分享入口已删除，避免手机上导出后找不到文件）。Windows 还可导出单条会话与全部历史，**导出时一律弹系统「另存为」对话框让用户选保存位置，默认目录是软件自己的数据目录（`<应用目录>\userdata\exports`）**，导出后 SnackBar 给出完整路径并提供「打开所在目录」。
  - 交给资源管理器对话框的预填路径**必须归一化成纯反斜杠**（`normalizeForDialog`）：`Directory('$root/exports')` 拼出来的
    路径混用正反斜杠时，`GetSaveFileNameW` 会以 `FNERR_INVALIDFILENAME`（`CommDlgExtendedError = 0x3002`）直接失败 ——
    用户看到的就是「点了导出什么都没发生」（用户反馈 2，本轮实测定位）。
  - 「对话框返回 0」要区分**用户取消**（错误码 0）与**真实错误**（错误码非 0）：后者必须让界面报「导出失败：…」，
    错误码同时写进日志，不能假装成「已取消导出」。
- 收藏与标签：M6 之后再做。

## 6. AI 分析

完整契约见 `ai-contract.md`，此处只列行为要求：

- 输入是**整张截图**（多页时是同一题的 1..6 页，一起送入；页序由模型自行判断纠正，用户需求 4 / 用户反馈 14），不裁剪、不预先 OCR。
- prompt 要求模型自己在图中寻找全部题目（含题号、题干、选项），忽略浏览器地址栏、聊天窗口等无关元素，并按阅读顺序输出。
- prompt 同时要求：只有答案没有题干的内容**不输出**；题干在但选项不全时仍输出并标记 `incomplete` + `answer_is_guess`；尽量识别图中原本印着的题号；**阅读类题目把材料原文写进 `material`（`stem` 只写问题）**；**主观题 `answer.text` 分点、换行、带序号**；只有材料没有题目的页不丢弃（用户反馈 14/15）。
- 输出必须是结构化 JSON；解析失败要能容错（剥离 markdown 代码围栏、截取首尾大括号、重试一次并附加更严格的系统提醒）。
- 同一 `image_hash` + 同一 `prompt_version` 在 30 天内命中缓存直接回放，不重新调用（**仅单页**；多页强制真实调用）。
- 每日调用上限默认 200 次，可配；达到上限时明确提示而不是继续静默失败。
- 每次调用记录 `prompt_version`、模型名、耗时，便于回溯「为什么上次答对这次答错」。

## 7. 同步与离线

完整算法见 `data-model.md`。行为要求：

- 两端本地各有 SQLite；所有写入同时产生一条 `sync_ops` 操作日志，用于增量同步。
- Windows 在线时通过 WebSocket 实时推送；断线后靠操作日志补齐。
- 图片文件不随操作日志传输：先传元数据（hash / 尺寸 / 路径），文件按需后台补传（最近约 200 张）。
- 冲突用 Lamport 时间戳 + `device_id` 字典序决胜，且**字段级** LWW。
- 用户手改过的字段打 `user_edited`，AI 重新分析不覆盖，除非用户点「用新结果覆盖」。
- 删除是软删除（tombstone），30 天后且所有对端已确认再物理清理。

## 8. 失败与降级矩阵

| 场景 | 必须的行为 |
|---|---|
| 未选择任务合集就发起识别 | **拒绝**：Windows 端提示「请先新建或选择一个任务合集」；服务端对手机返回 `409 no_active_collection`；安卓提示「请先在电脑上选择任务合集」（用户需求 8/12） |
| 多页识别中缺页 | 服务端任务标记 `failed`（`internal`，文案指明第几页），**不得**用残缺页序出答案；本地暂存区在提交后即清空，不会重复提交 |
| 多页超过页数上限 | 达到上限时提示「已达上限」并自动上传本次全部页面，不静默丢弃也不无限追加 |
| Windows 不在线（Android 发起） | 本地入库为 `queued`，UI 明确显示「已排队，Windows 上线后自动分析」；Windows 上线后自动补跑并通知 |
| AI 超时 | 按重试策略重试；最终失败 → 会话标记 `failed`，保留图片，提供「重试」按钮，不丢数据 |
| AI 返回 401 / 403 | **不重试**，提示「API Key 无效或无权限」，跳到设置页 |
| AI 返回 429 | 按退避重试；仍失败则提示「触发限流，稍后重试」 |
| AI 返回非法 JSON | 容错解析 → 失败则附加严格提醒重试 1 次 → 仍失败保留原始返回文本供查看，并标记需复核 |
| 图中没有题目（`questions: []`） | 提示「未识别到题目」，提供「手动框选重试」（默认关闭的功能在此处临时启用）与「重新分析」 |
| 截屏得到全黑图 | 提示「该应用禁止截屏」，提供「从相册选图」通路；不实现绕过 |
| 悬浮窗 / 无障碍 / 通知权限被拒 | 明确列出缺哪一项权限、会导致哪些功能不可用，给跳转按钮 |
| MediaProjection 会话失效 | 清除旧会话状态，下次点击时提示重新授权，不静默失败 |
| 配对码错误 / 过期 | 提示原因与剩余时间；连续失败触发锁定期并显示倒计时 |
| Token 失效或被吊销 | 提示「已解除配对」，引导重新扫码 |
| 磁盘空间不足 / 图片写入失败 | **结果优先**：答案照常显示，只提示图片未保存 |
| 局域网出现陌生设备尝试连接 | 拒绝（token 认不出一律 401）。**不再在设置页显示「无效连接尝试」提示**（M47 用户实测反馈：手机端每秒一次的合法轮询在未配对/换过 token 时也会被判成「无效尝试」，提示会一条条往上加，属于误报；见 `DECISIONS.md`） |
| 同步 ops 数量过多 | 触发快照折叠（见 `data-model.md`），不得因此卡住启动 |

## 10. 安全与隐私

- AI API Key **只存 Windows 端**，用 Windows DPAPI（`CryptProtectData`，当前用户作用域；自研 `WindowsSecureStore`，见 `DECISIONS.md` 2026-09-16 的 M3 行），绝不进明文 SQLite；设置页只回显尾 4 位。
- 配对：Windows 显示二维码（含 host / port / 配对码 / 服务端 device_id）+ 6 位配对码。配对码有效期 **5 分钟**，每分钟最多 5 次尝试，累计 10 次失败锁定 60 秒。
- 配对成功后下发长期 token（32 字节随机 hex）。Windows 端只保存 token 的 SHA-256 哈希；Android 端用 AndroidX Security 的 `EncryptedSharedPreferences`（`AndroidOptions(encryptedSharedPreferences: true)`）保存 token。**切换存储实现会让旧值读不出来**（两种实现落在不同的 prefs 文件里），表现为「需要重新配对一次」；读取异常时按「未配对」处理并提示重新扫码，界面不得卡在加载中。
- 除 `/api/v1/pair` 外所有接口要求 `Authorization: Bearer <token>`。
- Android 上传接口限流：每分钟 30 次。
- 局域网明文 HTTP 是**已知且接受的**前提（仅可信局域网），Android 需 `network_security_config.xml` 放行；不做自签证书（避免用户的信任链负担），在此前提下仍需评估 token 泄露的风险：同网攻击者若拿到 token 即可读写数据，因此提供「吊销设备」入口作为处置手段。
- **Android 数据不出本机**（用户 2026-09-20 拍板）：`android:allowBackup="false"` **并且** `dataExtractionRules` 把云备份与换机直传（D2D，Android 12+ 由该文件控制、`allowBackup` 管不到）两个域都排除。代价是换机不再自动恢复历史与设置。
- Android 应用包名为 `com.quizsync.android`（原 `com.example.quizsync_android` 属被保留的示例命名空间）。包名变更意味着**旧版必须先卸载才能装新版**，不提供覆盖升级路径；`namespace` 与 Kotlin 包路径保持 `com.example.quizsync_android` 不变（它只决定 R 类与相对类名的解析，不是安装身份）。
- 图片会上传到用户自己配置的第三方 AI 服务：**隐私告知在「首次保存 API Key」时展示一次**（M34 第 1 条，取代原来的「首次分析前弹窗」），确认后才写入这个 Key；点「暂不使用」则不保存并明确提示。**识别流程里不再弹任何告知窗**（那时用户常常已经在别的应用里，弹窗既打断又容易被忽略）。
- 提供「不保存图片文件（只保留文本结果）」开关。
- 日志中不得出现 API Key 与 token 明文。
